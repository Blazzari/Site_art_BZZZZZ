# Audit et reprise — 11 octobre 2026

## Périmètre et conclusion

Revue des sources Astro/TypeScript, styles, contenu, catalogue d’images, scripts,
configuration et workflow GitHub Pages. Le socle est adapté à un petit portfolio
statique : contenu séparé du rendu, composants réutilisables, peu de dépendances,
pas de backend ni de données utilisateurs collectées. Ceci n’est ni un test
d’intrusion ni une certification de conformité WCAG.

## Corrections de cet audit

- Les 28 fichiers publics ont des noms descriptifs par rubrique. Les références
  du catalogue ont été mises à jour ; les octets des photographies sont conservés.
- Le validateur des images vérifie aussi les limites des cadrages et rejette les
  blocs EXIF/XMP. Les dimensions et alternatives textuelles sont contrôlées.
- La navigation clavier suspend la rotation ; Lecture peut désormais réellement
  la relancer. Le changement de préférence d’animation ne réactive plus une pause
  explicite. La visibilité minimale de rotation est de 25 %.
- Le composant inutilisé SectionLabel a été supprimé et les imports regroupés.
- Le README vide a été remplacé par un guide d’installation, d’architecture,
  d’ajout de projets et de déploiement. Les guides images/galeries ont été actualisés.

## Contrôles effectués avant push

- `pnpm validate` : types sans erreur ni avertissement ; 28 images contrôlées,
  cinq tests de configuration de déploiement réussis, format Prettier conforme,
  build statique et contrôle de l’export réussis.
- `pnpm audit` : aucune vulnérabilité connue signalée à la date du contrôle.
- `git diff --check` : aucun problème d’espacement.
- Navigateur Chromium : largeurs 390, 768 et 1440 px sans débordement horizontal
  du document. Images chargées contrôlées sans erreur à 1440 px.
- Mobile : ouverture/fermeture du menu, fermeture du dialogue par Échap avec
  retour du focus, passage à l’image suivante au clavier et reprise via Lecture.
- Desktop : ouverture du dialogue et commandes dans la hauteur disponible.

Les actions GitHub sont épinglées à des SHA et disposent de permissions limitées.
Le build utilise le lockfile. Les sources ne contiennent pas d’injection HTML
brute ni d’exécution dynamique de code ; l’unique lien de service externe du
contenu est Instagram. Le contrôle de l’export recherche chemins locaux, clés,
tokens courants, fichiers privés et source maps ; cette détection n’est pas
exhaustive et ne remplace pas un audit de l’historique Git.

## Points restant à valider ou améliorer

1. Tester sur vrais iPhone/Android : gestes diagonaux, inertie, barres du navigateur,
   zoom et lecteur d’écran. Les tests de viewport ne les remplacent pas.
2. Les photos issues du PDF peuvent manquer de définition en vue agrandie.
   Obtenir les originaux avant de promettre une qualité Retina. Le catalogue
   sert un fichier par photo ; des variantes responsives restent une amélioration.
3. Mesurer les performances sur réseau mobile réel (LCP, CLS, INP). Aucun score
   de performance ni conformité d’accessibilité complète n’est revendiqué ici.
4. Confirmer crédits et droits des contenus. Le `noindex` reste volontaire pour
   la preview ; il faudra décider de son retrait au lancement public.
5. Le déploiement Pages reste manuel. Un workflow de push vert valide le code,
   mais ne publie pas le site : lancer Site → Run workflow sur main pour publier,
   puis contrôler l’adresse fournie par le job deploy.

## Reprendre sans perdre le contexte

Lire AGENTS.md, README.md, ce rapport, puis `git status` et le dernier workflow
**Site** correspondant au SHA de `main`. Ne pas déduire le statut du dernier push
à partir d’un ancien run rouge ou d’un run Dependabot. Ne pas écraser des changements
locaux et ne pas forcer le push. Le précédent commit vérifié avant cet audit était
`86e2567` (run GitHub 38175477503 réussi).

Nettoyage complémentaire : suppression des six `.gitkeep`, des six anciennes
images inutilisées et des trois documents historiques DRAFT-V1, AUDIT-RESPONSIVE
et TYPOGRAPHY, devenus contradictoires avec le site actuel. Ils restent dans
l’historique Git. Les règles de typographie utiles sont résumées dans le README.
